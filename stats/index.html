How many people have it, and how many are running it

Two different things are counted here, and they move independently. New downloads is the landing page's own button counter — one per browser, all time. Everything else is derived from CDN traffic the app already generates checking for updates, which includes existing installs downloading a new version. No telemetry, nothing new collected. The same numbers come out of node scripts/stats.mjs.

Adoption

Updates only ever jump to the newest release, so the last one a machine took is the one it runs. The top row is current adoption; the rows below it are how earlier rollouts went, dimmed because they're superseded rather than still populated.

Installs running, by hour

Each running app fetches CHANGELOG.md every 30 minutes, so hourly requests ÷ 2 is a headcount.

Read the flat parts, not the peaks. A release makes every updated machine restart and poll again immediately, so release hours count the same handful of computers more than once. The steady median between releases is the real number.

Installer fetches, by hour

Actual .dmg / .exe / .AppImage / .zip fetches from the CDN — the bandwidth behind a release, and the only traffic here that costs real money. Counts auto-updates, so shipping a version spikes this while "new downloads" above does not move: those are existing installs taking the update, not new people.
